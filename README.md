# oplus battery kit

面向 OPPO / 一加 / 真我 `oplus_chg_v2` 充电框架的电池参数工具包。
设备树读写、DTBO 容器、AVB 处理与签名均在模块内实现，不依赖任何外部二进制。

> 本模块会修改电池管理与充电控制行为，存在硬件损坏与设备无法开机的风险。
> 使用前请阅读文末的 [免责声明](#十二免责声明)。

刷入包在 [Releases](../../releases) 下载：

| 文件 | 说明 | 体积 |
|---|---|---|
| `oplus-batt-kit.zip` | 主模块，Magisk / KernelSU / APatch 刷入 | 约 130 KB |
| `obk-restore.zip` | 救砖包，第三方 recovery 可刷，回刷原厂 dtbo | 约 3 KB |

也可以自行构建，见[第十节](#十构建)。

## 二、安装

刷入后三条路径任选：

```
音量+    推荐配置，两次按键完成
音量-    逐项选择，按功能逐个确认
电源键   仅安装，暂不改 dtbo，之后全部在 WebUI 里配
```

安装流程会依次做：识别机型、探测 AVB 状态、DTBO 空转往返校验、
快照原厂值、导出救砖备份并要求确认已拷到电脑、固化 AVB 参数、应用配置。

**刷完拔掉充电器再重启。** 深放计数刷新只在未充电时有意义。

### 一次刷入，此后不用再刷

安装时已把原厂值快照到 `/data/obk`、AVB 参数固化到本地，之后任何配置改动
都可以在 WebUI 里勾选并一键应用，不需要重新刷包，也不需要保留官方 dtbo 镜像。

## 三、AVB 处理

模式由 `avbctl get-verification` 自动判定，直读 vbmeta 分区标志位，
属性伪装影响不到它。

| AVB 校验 | dtbo 形态 | 模式 | 需官方 dtbo 镜像 |
|---|---|---|---|
| 已关闭 | 带 footer | 自签（默认），也可改用拼接 | 否 |
| 已关闭 | 无 footer | 裸写 | 否 |
| 开启 | 带 footer | 免解拼接 | 是 |
| 开启 | 无 footer | 拒绝安装 | — |
| 未知 | 带 footer | 免解拼接（保守） | 是 |
| 未知 | 无 footer | 拒绝安装 | — |

需要官方镜像时，把对应系统版本官方包里的 `dtbo.img` 改名为 `dtbo_stock.img`
放到内置存储根目录。

免解拼接会原样保留官方 vbmeta，但其中的 hash descriptor 描述的仍是原版载荷，
与改后的数据对不上。它能生效的前提是本机没有强制校验 dtbo 哈希。

自签会用模块自带的密钥重新生成 vbmeta 并签名，签名本身完整有效，
但密钥不是厂商的，所以必须先关闭 AVB 校验。

另有一条永不触发的保险丝：若 `/proc/cmdline` 显示引导程序处于锁定状态，
直接拒绝写入，因为锁定状态下写坏 dtbo 无法用 fastboot 回刷。

## 四、安全设计

### 写入前

- **空转往返校验**：拆开 dtbo 再原样打包，与原容器逐字节比对，不过就一个字节都不写
- **元数据保留**：打包器逐字节保留每个条目的 `id` / `rev` / `custom[0..3]` 与原顺序
- **读回断言**：每条规则自带 verify，写入前逐项校验，不符则整体放弃
- **二次解析**：重打包后重新解析，条目数、FDT 有效性、长度自洽
- **尺寸与 AVB**：输出必须精确等于分区大小
- **写后回读**：写完立即读回比对 MD5，不符则用原镜像恢复

### 基线重建

每次应用都从原厂快照重建，而不是增量叠加：先把所有规则触及的属性与子树
写回原厂值，再按配置逐个应用启用的段。关掉一个功能就是真的关掉，不留残留。

快照分两级：`set` 类记录属性原值，`rm` 类序列化整棵子树。所以被删除的
LCF 节点也能完整还原。

### 救砖

安装时强制把原厂 dtbo 导出到 `/sdcard/obk_backup/`，附 MD5 与一份填好本机
实参的救砖说明，并要求确认已拷到电脑后才继续。

真变砖时手机内部的备份取不出来，务必先拷走。恢复途径：

```bash
fastboot flash dtbo_a dtbo_<机型>_<指纹>.img
```

装了第三方 recovery 的话，直接刷 `obk-restore.zip` 即可，它会自动匹配当前
系统版本的备份、校验 MD5、写回并回读比对。

## 五、规则语法

功能以声明式规则描述，机型适配是写规则而不是写补丁。

```ini
[!rm_lcf]                              # ! 前缀表示强制段，不进菜单
  title    移除 LCF 充电结束策略
  suggest  cv_daemon
  node     &oplus_ufcs_charge
  rm?      ufcs_oplus_lcf_strategy     # ? 表示不存在则跳过
  rm?      */ufcs_oplus_lcf_strategy   # 支持通配

[ddrc]
  title    解除深放降容
  default  on
  node     &oplus_mms_gauge
  prefer   silicon_p_*                 # 有电芯子节点就改子节点
  read     $uv = deep_spec,uv_thr      # 现场读原厂地板值
  set      deep_spec,count_step = <0 0 0>
  set      deep_spec,term_coeff = <0 0 0>
  each     ddrc_strategy/strategy_ratio_range_* : strategy_temp_* = <0 $uv $uv 0>
  verify   deep_spec,count_step == <0 0 0>
```

| 指令 | 作用 |
|---|---|
| `node &label` | 经 `__symbols__` 解析标签作为作用域 |
| `prefer glob` | 存在匹配子节点则改以它为作用域 |
| `fixup prop` + `match` | 改从 `__fixups__` 取目标 |
| `read $v = prop` | 现场读属性首个 cell 到变量 |
| `set [路径 :] 属性 = 值` | 设置属性，不存在则创建 |
| `each [路径 :] 通配 = 值` | 批量设置，仅改已存在的 |
| `rm` / `rm?` | 删除子节点 |
| `verify 属性 == 值` | 读回断言 |

值的写法：`<数组>`（十进制或 `0x`）、`"字符串"`、`!`（空属性）。
冒号分隔子节点路径与属性名，因为两者都可能含逗号。

原厂数值不内置在规则里，安装时从设备现场读取，所以不会把某个特定
系统版本的参数固化进来。

## 六、命令行

模块装好后 `obk` 常驻在模块目录，可直接调用。

```
obk avb    detect | cache --stock <img> | graft --in A --out B | sign --in A --out B
obk dtbo   list | unpack --dir D | selftest
obk dt     syms F | get F <节点> [属性]
obk prof   list | show <id> | apply [--dry-run] [--force] | revert
obk snap   create [--source live|stock --stock <img>] | info
obk cfg    get [key] | set k=v ... | reset
obk batt   status | proto <pps|ufcs|svooc> [on|off] | faketemp [on|off]
           lockvotes [on|off] | auth <ufcs|sec> | refresh
obk daemon start | status
```

全局选项：`--json` `--verbose` `--quiet` `--device <代号>` `--dtbo <文件>`
`--root <目录>` `--profiles <目录>` `--avb <graft|selfsign|raw>`

`--dtbo` 与 `--root` 让整套引擎可以在主机上对文件跑完整流程，测试不需要设备。

退出码：`0` 成功、`2` 参数错、`10` 校验未过可越过、`11` 硬阻断、
`20` 缺官方镜像、`21` 快照缺失、`30` 机型不支持。

## 七、协议开关的节点适配

协议开关落在哪个 sysfs 因内核版本而异，模块用候选表而不是硬编码：

```
# profiles/nodes.conf
proto_pps   path=/sys/class/oplus_chg/common/pps_disable     on=0 off=1
proto_pps   path=/sys/class/oplus_chg/common/cpa_pps_enable  on=1 off=0
```

同一个键可以有多行候选，取第一个实际存在的路径。`obk batt proto pps` 返回
`unknown` 说明没有命中任何候选，在这个文件里补上本机的实际路径即可，
不需要重新编译。

## 八、协议认证载荷

`profiles/auth_ufcs.bin` 是 16 字节固定数据，开机由 `service.sh` 经
`ioctl 0x40016601` 写入 `/dev/ufcs_dev`。作用推断为 UFCS 协商高功率档前的
认证数据 —— 与 dtbo 功率表是两回事：功率表决定内核愿意跑多大电流，
这一步决定协议层面能否谈到那一档。

下发失败时静默跳过。调用点只有 `service.sh` 一处且带文件存在判断，
不影响任何其他功能。删掉该文件即可停用，不需要重刷模块，
也可用 `obk cfg set auth_ufcs=0` 关闭。

`/dev/sec_dev` 那条分支的命令行入口 `obk batt auth sec` 仍在，是通用分发逻辑，
本包不附带对应载荷。

## 九、恒压涓流守护

接管充电末段，状态机为 升流 - 恒压 - 涓流 - 判满，按配置的目标电压逐步收流，
并按温度档位回退电流上限。参数全部可在 WebUI 里调整。

这一项直接控制充电电流，默认关闭。启用前请确认自己了解每一项参数的含义，
并按实际设备核实取值。

由于 LCF 是强制移除的，内核不再自行判满，不启用守护时充满后可能仍有小电流。

## 十一、风险

- 电池被允许放到更低电压，长期如此会加速容量衰减。这是拿寿命换可用容量。
- 温度墙与大电流会显著增加发热与电池负荷。默认关闭，开启前请自行评估。
- 写 dtbo 分区有变砖风险。务必先把救砖备份拷到电脑。
- 系统更新后 dtbo 会被覆盖，需要重新应用。开机自检会在管理器里提示。
- 若存在内核态 dtbo 复写程序，修改可能不生效。
- 卸载模块不会还原 dtbo。dtbo 是分区级修改，与模块挂载无关。
